Branching Strategy: Use main for stable production code, develop for integration, and feature/<issue-id>-<short-name> for new features (e.g., feature/12-feedback-history).

Commit Message Format: Use conventional commits (e.g., feat(auth): add login validation, fix(db): resolve user table constraint).

Pull Request Rules: Every PR must be reviewed and approved by at least one team member before merging into develop or main.
